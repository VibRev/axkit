# 评测报告：精简重构与自带 MCP（2026-10-24）

本报告覆盖两次运行：

- **CLI 与 MCP 对比**（`mcp-full`，140 个会话）：在还带 helper 的版本上跑。
- **第 3 轮**（`r3-slim`，126 个会话）：在精简后的版本上跑。这一版去掉了 helper，删了一批 flag，`ref` 改为检索安装目录，并新增了 `idax mcp` / `bnx mcp`。

两次运行条件相同：同一台 Linux 机器（IDA 9.4、Binary Ninja 6.0.10905），同样 7 个任务，每组跑一次。下文数字除特别说明外，都是每个会话的中位数。

## 结论

1. **去掉 prelude 里的 helper 之后，没有哪一项变差。**
   - agent 直接写 `ida_funcs`、`idautils`、`ida_hexrays`、`bv.functions`，成功率没变，大多数组的总 token 持平或下降。
   - codex 改善最大：token 降了 17–30%，耗时从 79–84 s 降到 34–37 s。
2. **省 token 的关键是"代码模式 + 很小的工具面"，而不是 CLI 还是 MCP。**
   - 我们的 MCP 只有 5 个工具，工具定义约 2 KB。在 claude 上它是 token 最少的接法，每个会话 31–32k，比我们自己的 CLI 少约 1/3。
   - 比官方 ida-mcp（工具定义 7 KB）少 40–50%。
   - 只有大 schema MCP 的 1/4 到 1/7，比如 ida-headless-mcp（90 个工具，schema 411 KB）和 bn-headless-mcp（51 个工具）。
3. **输出有上限，在 codex 和 grok 上很重要。** 官方 ida-mcp 不截断输出，在这两个 harness 上，工具输出量是我们的 2–5 倍。
4. **`ref <words>` 取代了 helper 原来的作用。**
   - 查询时现读引擎安装目录里的 Python 文件，返回签名、`文件:行号` 和 docstring。
   - IDA 有 1.6 万个定义，BN 有 5.7 千个；一次查询 25–45 ms。
   - 查询词是标识符时，API 结果排在最前。

## 设置

- **任务**（见 `idax/eval`、`bnx/eval`），fixture 都是 AArch64 ELF：
  - password
  - xor-flag
  - add-cipher
  - calls-system
  - rename-save
  - spill-needle
  - long-function：反编译结果约 40 KB 的函数，远超 8 KB 的输出窗口，答案只能从 spill 文件或过滤后的输出里拿到。
- **harness 与模型**：
  - claude：Claude Code，模型是 `claude-sonnet-5-5`；
  - codex：默认模型；
  - grok：`grok-4.7-build`。
- **组**（`<h>` 代表 harness 名）：

  | 组 | agent 拿到的接法 |
  |---|---|
  | `<h>` | CLI 在 PATH 上，不装 skill |
  | `<h>-skill` | CLI，并把 skill 装进项目的 skill 目录 |
  | `<h>-mcp` | `idax mcp` / `bnx mcp`；PATH 上没有 CLI，也不装 skill |
  | `<h>-idamcp` | 官方 Hex-Rays ida-mcp（只在对比运行里） |
  | `<h>-ihmcp` | ida-headless-mcp（只在对比运行里） |
  | `<h>-bhmcp` | bn-headless-mcp（只在对比运行里） |

- **成本怎么算**：
  - claude 按 token 和 `prices.toml` 重新计算；
  - grok 用它自己报的数；
  - codex 不报成本，只统计 token。

## 失败分析

**第 3 轮：idax / grok-skill / long-function**

- 工具链路没有问题：agent 在 exec 里把函数中的 32 条 `STRB` 过滤出来，没有碰到截断，每个偏移上的字节也都取对了。
- 最终答案写成了 `LONG{spills_files_are_read_9b2e}`，多了一个 s。
- 这是模型拼字符串时的笔误，与工具无关。

**对比运行**

- claude / ida-headless-mcp：一次被 Sonnet 的安全分类器拦截，与工具无关。
- grok / ida-headless-mcp：agent 逐字节拼答案时漏了一个字母。

## 其他观察

- **grok 不认带 `.` 的工具名。** grok 会跳过名字里带 `.` 的 MCP 工具，bn-headless-mcp 的工具名全都带 `.`，所以在 grok 上一个都用不了。我们的工具名（`exec`、`ref`、`save`、`close`、`list`）都不带点。
- **官方 ida-mcp 的三条经验都成立，我们都照搬了**：工具少；只注入模块，不加 helper；明确告诉 agent"不要猜 API，先查"。
  - 只有一条没照搬：它在关闭时自动保存。idax 和 bnx 不调用 `save` 就不写盘。
- **MCP 没有 `open` 工具。** `exec` 遇到没打开的目标会自己打开，并等分析完成。这一轮没有 agent 因为缺 `open` 而多绕路。
- **评测框架本轮修了两处**：
  - grok 写 `trusted_folders.toml` 时自己不加锁，现在所有评测会话共用一把文件锁；
  - grok 可能在进程退出后才写出会话目录，现在 runner 在整轮结束时再扫一遍，只删本轮留下的条目。

## 这次重构改了什么

- **prelude**：idax 从 418 行减到 191 行，bnx 从 310 行减到 128 行。只留下执行器：
  - 取最后一个表达式的值；
  - 报错时只显示用户代码的 traceback；
  - did-you-mean；
  - 结果转不成 JSON 时输出 `str(obj)`；
  - 处理 SIGINT。
- **删掉了**：
  - `--keep`、`--no-wait`、`--truncate head-tail`；
  - 分析未完成时的 exit 2；
  - bnx 的 undo 组和未保存状态跟踪；
  - list 和 ref 的 JSON 输出（`--json` 只留给 exec）；
  - 除 `<TOOL>_MAX_BYTES`、`<TOOL>_TIMEOUT` 以外的环境变量；
  - 按 harness 区分的默认值表、`Fallback::Local`、`rex::int`。
- **新增了**：
  - `ref <words>` 的安装目录 API 检索（`rex::pyapi`）；
  - stdio MCP server（`axkit::mcp`、`rex::mcp`）。

## 局限

- **每组只跑一次。** 两组之间 20% 以内的差距都在噪声范围内。
- **这套任务分不出工具的能力高低。** 几乎每种接法都能全部通过，所以它实际衡量的是成本。
- **只和同口径的数据比。** 基线是 `mcp-full`：同一台机器、同样 7 个任务、同样每组一次；不混入口径不同的历史轮次。

## 复现

```sh
cd axkit/eval
export BINARYNINJADIR=/path/to/binaryninja   # Binary Ninja 安装目录
target/release/axkit-eval run ../../idax/eval/suite.toml ../../bnx/eval/suite.toml \
  --group claude --group claude-skill --group codex --group codex-skill --group grok --group grok-skill \
  --group claude-mcp --group codex-mcp --group grok-mcp \
  --reps 1 --jobs 8 --per-harness 4 --out target/eval-data/r3-slim
target/release/axkit-eval compare target/eval-data/mcp-full/results.merged.jsonl target/eval-data/r3-slim/results.jsonl --by suite,group
```

原始数据在 `target/eval-data/{mcp-full,r3-slim}`，不提交。
